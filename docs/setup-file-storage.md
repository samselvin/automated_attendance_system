# File storage setup

Section 43 requires uploaded files (Leave/OD supporting documents, per
Section 15) to go through type/size validation, private storage, and
time-limited signed URLs — never a public bucket, never an executable
file. The schema is ready for this (`FileAsset` in `prisma/schema.prisma`,
and `LeaveRequest.documentFileId` / `Event.documentFileId` /
`ImportJob.fileId` all reference it), and `.env.example` already declares
the S3-compatible credential this needs:

```
STORAGE_ENDPOINT=""
STORAGE_BUCKET=""
STORAGE_ACCESS_KEY_ID=""
STORAGE_SECRET_ACCESS_KEY=""
```

**This is the one place where the schema is ahead of the implementation.**
No storage credential has been provided, and — unlike SMS, which has a
working `dev` provider that logs instead of sending — there is no upload
API route, no presigned-URL generation, and no upload control in the
student's "Apply for Leave/OD" form (`src/app/student/attendance/apply/`)
yet. A student can submit a Leave/OD request today with no attached
document; `documentFileId` is simply left null. See
`docs/pending-credentials.md`.

## Once a credential exists, here's the intended shape

1. **Provision an S3-compatible bucket** — AWS S3 directly, or a
   cheaper/simpler alternative like Cloudflare R2 or Backblaze B2 (both
   speak the S3 API, so the same `@aws-sdk/client-s3`-based code works
   against any of them by pointing `STORAGE_ENDPOINT` at the provider).
2. **Keep the bucket private** — no public read access. Every download
   goes through a short-lived signed URL generated by the app, never a
   permanent public link.
3. **Add an upload API route** (e.g. `POST /api/files`) that:
   - Requires an authenticated session.
   - Validates the file's declared MIME type against an allow-list (PDFs
     and common image types are enough for medical certificates/OD
     proof — never allow `.exe`, `.sh`, `.js`, etc.).
   - Enforces a size cap (a few MB is plenty for a scanned certificate).
   - Streams the file straight to the bucket under a random
     `storageKey` (never the original filename) and creates the
     `FileAsset` row.
   - Returns the new `FileAsset.id` for the client to attach as
     `documentFileId` on the Leave/OD submission.
4. **Add a download route** that checks the same RBAC rules the rest of
   the app uses (the requester must be the student, their Class Advisor,
   the HOD, or an Admin in scope) before generating a signed GET URL with
   a short expiry (a few minutes is enough — the client fetches it
   immediately).
5. **Wire a file input into** `src/app/student/attendance/apply/apply-form.tsx`
   for Leave/OD types where a document is expected, and a small "View
   document" link into the teacher/admin decision screens
   (`src/app/teacher/leave-requests/`, `src/app/admin/leave-requests/`).

None of this is stubbed with fake data or a mock endpoint — it simply
doesn't exist yet, per Section 54's rule that an integration needing an
external credential should be documented rather than faked.
